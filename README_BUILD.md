# VeloForge — Build & Installer Guide

This document explains how to build the `VeloForge_Setup.exe` Windows installer from source.

---

## Prerequisites

Install all of the following before running the build script.

| Tool | Version | Download |
|---|---|---|
| **Node.js** | 20 LTS or later | https://nodejs.org |
| **.NET SDK** | 9.0 | https://dotnet.microsoft.com/download/dotnet/9 |
| **Python** | 3.11 or 3.12 | https://python.org/downloads |
| **Inno Setup** | 6.x (6.3.3+) | https://jrsoftware.org/isdl.php |
| **PyInstaller** | 6.x | installed automatically by the build script |

> [!IMPORTANT]
> Install **Inno Setup 6.x** to the default path (`C:\Program Files (x86)\Inno Setup 6\`). The build script locates `ISCC.exe` there automatically.

> [!NOTE]
> The build script installs `pyinstaller`, `pyvista`, and `numpy` via `pip` automatically in Step 3. You only need a working Python installation on your PATH.

## Repository layout (before building)

```
d:\pico\
├── gui.py                  ← Python GUI entry point
├── pico.csproj             ← C# simulation pipeline
├── web\                    ← Next.js login page
├── configs\                ← Default config files (must exist)
├── assets\
│   └── veloforge.ico       ← App icon (must exist before build)
├── LICENSE.txt             ← Required by setup.iss
├── build_installer.ps1     ← ← Run this
├── setup.iss               ← Inno Setup script
└── verify_install.ps1      ← Run after installation to verify
```

> [!IMPORTANT]
> You must supply the simulation binaries **before** running the build script. Place them at:
> ```
> fTetWild.exe      →  fTetWild\build\Release\FloatTetwild_bin.exe
> ccx.exe           →  calculix\CalculiX-2.21.0-win-x64\bin\ccx.exe
> ccx2paraview.exe  →  on system PATH  (or add to $BinSources in build_installer.ps1)
> ```

## Step-by-step build instructions

### 1. Clone / pull the repository

```powershell
git clone https://github.com/ochidesoim/pico.git
cd pico
git checkout main
git pull
```

### 2. Create required assets

If `assets\veloforge.ico` doesn't exist yet, create it from `logo.ico`:

```powershell
# Quick copy — replace with a proper multi-size .ico if available
Copy-Item logo.ico assets\veloforge.ico -Force
```

Ensure `LICENSE.txt` and `configs\` exist in the root:

```powershell
# LICENSE.txt — must contain the engineering disclaimer at the top
if (-not (Test-Path LICENSE.txt)) {
    @"
ENGINEERING DISCLAIMER: All outputs generated by VeloForge are design
aids only and do not constitute engineering certification. Independent
validation by a qualified engineer is mandatory before use on any
physical vehicle.

(c) VeloForge Engineering. All rights reserved.
"@ | Set-Content LICENSE.txt
}

# Minimal configs directory
New-Item -ItemType Directory -Force configs | Out-Null
Copy-Item config.json configs\default_config.json -Force
```

### 3. Update binary checksums (security step)

Open `build_installer.ps1` and replace the placeholder checksum values with the real SHA-256 hashes of your binary builds:

```powershell
# Get the actual hashes
(Get-FileHash "fTetWild\build\Release\FloatTetwild_bin.exe" -Algorithm SHA256).Hash
(Get-FileHash "calculix\CalculiX-2.21.0-win-x64\bin\ccx.exe" -Algorithm SHA256).Hash
```

Paste the output values into the variables at the top of `build_installer.ps1`:

```powershell
$ChecksumFTetWild  = 'PASTE_HASH_HERE'
$ChecksumCcx       = 'PASTE_HASH_HERE'
```

> [!CAUTION]
> If you skip this step, the build will proceed with a warning but binary verification is disabled. Always set checksums for production builds.

### 4. Run the build script

Open a **regular** (non-admin) PowerShell window and run:

```powershell
cd d:\pico
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\build_installer.ps1
```

The script runs all 5 steps in sequence:

| Step | What it does | Output |
|---|---|---|
| 1 | `npm install && npm run build` | `web\out\` |
| 2 | `dotnet publish --self-contained win-x64` | `dist\pipeline\pico.exe` |
| 3 | `pyinstaller gui.py --onefile --windowed` | `dist\VeloForge.exe` |
| 4 | Assembles `dist\` layout, verifies checksums, downloads VC++ Redist | `dist\bins\`, `dist\redist\` |
| 5 | `ISCC.exe setup.iss` | `dist\installer\VeloForge_Setup.exe` |

> [!NOTE]
> The full build typically takes **5–15 minutes** depending on machine speed and internet connection (for VC++ Redist download).

If any step fails, the script prints a clear `[FAIL]` message and stops — it will never proceed past a failing step.

### 5. Find the output installer

```
dist\installer\VeloForge_Setup.exe
```

This is the single-file installer ready for distribution.

## After installing — run verification

After running `VeloForge_Setup.exe` on a test machine, open PowerShell and run:

```powershell
cd d:\pico
.\verify_install.ps1
```

Or, if installed to a custom directory:

```powershell
.\verify_install.ps1 -InstallDir "D:\MyApps\VeloForge"
```

Expected output:

```
╔══════════════════════════════════════════╗
║  VeloForge Installation Verification     ║
╚══════════════════════════════════════════╝

Check 1/7 — VeloForge.exe
[PASS] VeloForge.exe exists at install path

Check 2/7 — pico.exe (C# pipeline)
[PASS] pico.exe exists at install path\pipeline\

...

VeloForge installation verified — 7/7 checks passed
```

Any `[FAIL]` lines include a reason. Fix the reported issue and re-run.

## Troubleshooting

| Problem | Fix |
|---|---|
| `ISCC.exe not found` | Install Inno Setup 6.x to the default path or add it to `PATH` |
| `dotnet publish` fails | Install .NET 9 SDK (not just Runtime) |
| `pyinstaller: command not found` | Ensure Python is on `PATH`; the script calls `pip install pyinstaller` first |
| `ccx2paraview.exe not found` | Add it to `PATH` or add its path to `$BinSources` in `build_installer.ps1` |
| Installer > 500 MB | Check that `node_modules\` is not accidentally bundled (see `web\.gitignore`) |
| `[WARN] Checksum not set` | Replace placeholder values in `build_installer.ps1` as described in Step 3 |

## Constraints

- **Windows only** — no macOS or Linux targets
- **Inno Setup 6.x only** — will not compile with older versions
- **PowerShell 5.1+** compatible — do not use PS 4.x
- Build script requires **no admin rights** (Inno Setup compilation also runs without admin)
- The final installer **requires admin** during installation (normal for `Program Files` installs)
- All paths in scripts use **backslashes** for Windows compatibility
